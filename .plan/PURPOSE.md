## 1. 一句话定位

**Peingxious Dashboard = 一个 Obsidian 主页形式的玻璃拟态工作台，一个窗口解决所有日常面板问题。**

不是另一个 Dataview 替代品，不是 Tasks 插件的对手，不是社区主题市场 —— 而是一个**"打开 Obsidian 第一眼看到的指挥中心"**。

---

## 2. 核心问题（解决什么）

**多场景一站化**：用户每天要在多个面板/视图间跳转才能完成日常工作。

具体痛点：

- 备忘、待办、项目、资料库、提醒、天气、倒计时散落在不同的面板/插件
- 每次想"看一眼今天要做什么"都要在 5+ 个位置切来切去
- 缺乏**视觉统一**的个人指挥中心：Obsidian 偏纯文本，缺乏工作台型概览页
- 现有的 Dataview / Tasks 插件对纯笔记用户门槛太高，需要写查询语句
- 多分区内容无法在一个页面里**自由组合**（看板 / 列表 / 备忘 / 项目卡片混排）

---

## 3. 目标用户

**当前定位：个人使用**（非社区产品）。

- 单一作者（Peingxious）的个人工作流
- 不强求兼容所有 Obsidian 用户的边缘场景
- 可以接受"如果其他用户用不顺手，他们改用别插件即可"的姿态
- 优化目标：**作者自己的日常效率**，不是用户数

**隐含画像**：

- 重度笔记用户，每天高频打开 Obsidian
- 同时管理多个并行项目（工作 / 学习 / 生活）
- 喜欢可视化、不喜欢纯文本列表
- 愿意花时间配置工具换取长期效率

---

## 4. 核心差异化（4 个）

### 4.1 零代码转换笔记为仪表盘

**问题**：现有方案要用户学 Dataview DQL / JS 模板。

**本插件的做法**：扫描笔记的 `## H2` 标题 → 自动映射为分区 → 写回 `columns:` frontmatter → 一键打开为仪表盘。无任何代码。

**AI 开发约束**：新增分区类型时，**必须**同时支持被自动转换识别，转换流程不能成为二等公民。

### 4.2 玻璃拟态 + 主题预设

**问题**：Obsidian 社区主题众多但都是为**阅读**优化，不是为**工作台**优化。

**本插件的做法**：

- 自带 glassmorphism 风格（半透明、模糊、层次感）
- 12 种内置预设（Earth / Nordic / Aurora / Spring / Island / Tundra / Blossom / Haze / Ember / Jade / Matcha / Lilac / Eclipse）
- 同时跟随系统主题（Auto 模式）

**AI 开发约束**：视觉一致性 > 个性化。每加新组件必须遵守现有的 CSS 变量与卡片模型。

### 4.3 原笔记镜像，不存副本

**问题**：Tasks 插件 / Dataview 在内存里聚合数据，源数据改了不会自动更新对应视图。

**本插件的做法（TodoPlus）**：

- 用户指定 `[[dash002#To-do]]` → 插件**实时**从原笔记读取该 H2 下的清单
- 用户在仪表盘勾选任务 → 通过 `vault.process` 写回原笔记对应行
- **不存在第二份副本**，永远不漂移
- 一行只动一行，其他段落完全不动

**AI 开发约束**：任何"引用其他笔记内容"的新功能，**必须**遵循"原笔记即真相"原则，**禁止**复制缓存。

### 4.4 块状图规划项目面板（愿景）

**问题**：现有项目面板是**卡片墙**或**列表**——视觉上是"散点"。当项目复杂、任务多、依赖多时，看不到"整体规划感"。

**期望方案（待实现）**：

- **块状图**（不是思维导图）：像 Trello / Notion 一样，**有结构的图**
- 思维导图太"发散"，用户要的是"规划感"
- 项目面板应该一眼看到"我现在在哪一阶段 / 哪些模块并行 / 哪些阻塞"
- 任务方式驱动（不是自由节点连接）

**AI 开发约束**：

- 这是**未来方向**，不在当前功能列表中
- 现有的 Projects 卡片墙保留作为简单场景的 fallback
- 设计新项目视图时，**优先考虑块状图**，不要重蹈"卡片墙→任务列表→看板"的覆辙

## 5. 明确边界（不做什么）

### 5.1 不替代任务 / 数据库插件

- **不**与 Tasks 插件、Dataview 插件抢"任务管理"市场
- **不**实现 GTD / 番茄钟 / 四象限等任务管理方法论
- 番茄钟 / 倒计时是**小组件**（辅助），不替代专业工具

### 5.2 不与核心插件抢功能

- **不**重写文件浏览器
- **不**重写快速切换（Quick Switcher）
- **不**重写反链面板
- 如果有冲突，**让位给核心插件**

### 5.3 与 Templater / 社区插件的关系

- ✅ **可以调用** Templater 的接口（Templater 是命令式 API，可以触发）
- ✅ **不**被 Templater 调用（避免循环依赖）
- ❌ **不**做社区主题市场（专注做工作台，不抢主题饭碗）

### 5.4 不做的事（黑名单）

- ❌ 不做云同步 / 账户系统
- ❌ 不做插件市场 / 评分系统
- ❌ 不做移动端专属功能（跟随 Obsidian 移动端能力即可）
- ❌ 不做付费功能 / Pro 版

## 6. 整体框架（How）

### 6.1 入口结构

```
打开 Obsidian
  ↓
[右栏 Ribbon 图标]  →  打开 Dashboard 主页
  ↓
[主页] = 6 种分区自由组合（Banner + Memo + Todo + Projects + Notes + Library + TodoPlus）
[侧栏] = 侧边栏视图（最近文档 + 小组件：天气/热力图/番茄钟/阅读/倒计时/农历）
```

### 6.2 数据流

```
笔记 frontmatter (columns: 列表)
  ↓
DashboardView 读取 → 渲染分区
  ↓
用户操作 → vault.process 写回原笔记（单行精确写入）
  ↓
监听 vault 修改事件 → DashboardView 重新渲染
```

```

           ▼
```

## 7. 非目标

为了避免范围蔓延，以下场景**不**在本插件目标内：

- 多人协作 / 实时同步
- 移动端专属功能优化
- 跨平台（Windows / macOS / Linux）特性差异
- 商业化 / 付费版本
- 第三方插件 SDK / 扩展 API

如果未来用户提出这些需求，**应转给其他专门插件**，本插件保持"个人主页工作台"的纯粹定位。

---

## 8. 成功标准

对作者个人而言，本插件"成功"的定义：

1. **每日打开** —— 每天打开 Obsidian 的第一个动作就是打开 Dashboard
2. **单一入口** —— 日常任务不需要离开 Dashboard 即可完成
3. **零维护** —— 不需要每天手动整理卡片位置 / 拖拽对齐
4. **视觉愉悦** —— 看着舒服，**不像工具，像私人空间**

AI 在做任何功能决策时，应以这 4 条作为最终裁决标准。
